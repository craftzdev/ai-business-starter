# AI Business Starter

生成AI初心者が、AIを使った小さな事業アイデアを4段階で整理する日本語MVPです。
仕様は [Product AgentのPRD](docs/prd.md) を参照してください。

## 起動

リポジトリ直下の `preview.html` をブラウザーで開いてください。CSS・JavaScriptはすべて内包し、画像・外部フォント・外部API・パッケージの取得は不要です。通信なしで動作します。

ファイルを直接開いた場合のlocalStorage対応はブラウザーによって異なります。保存を安定して確認するには、Python 3の標準機能でローカル起動してください。

```sh
python -m http.server 8000 --bind 127.0.0.1
```

`http://127.0.0.1:8000/preview.html` を開きます。終了は `Ctrl+C`。再開時も同じブラウザーと同じURL（ポートを含む）を使ってください。現在のChrome・Edge・Firefox・Safariを想定しています。

## 使い方と保存仕様

- ホームの「次にやるべき一手」から、教材・具体例を読み、ワークを入力します。すべて必須で1〜500文字（Unicodeコードポイント数）。空白だけの入力は完了できません。段階1は2つの安全確認も必須です。
- 前の段階を完了すると次が開きます。入力は随時自動保存され、完了済み段階も編集できます。編集で条件を満たさなくなると、その段階以降の完了を解除します。後続の入力内容は保持するので、順番に再確認して完了できます。
- 4段階完了後に7項目のまとめと各項目への編集ボタンが表示され、次の一手には入力した検証行動が表示されます。
- localStorageのアプリ専用キー `ai-business-starter.v1` に、入力・安全確認・完了／開始状態・匿名ID・イベントをまとめて保存します。他のキーには触れません。ログイン、端末間同期、外部送信はありません。複数タブの同時編集には対応せず、最後に保存した内容が残ります。
- 保存に失敗しても現在の画面では編集できます。設定や容量を確認し、「現在の内容で保存し直す」を押してください。未保存の変更は再読み込みで失われます。
- 壊れたデータや未対応の保存形式を検出すると、空のワークと復旧案内を表示します。自動上書きは止まり、利用者が保存し直すか全削除するまで元の保存データを保持します。
- 全削除は確認ダイアログを使います。取消／Escapeでは保持し、確定すると入力・進捗・匿名ID・イベントを消します。保存先の削除に失敗した場合は理由と再試行を表示します。削除の再試行は、その間に画面で入力した内容も消します。

## 計測の確認

画面末尾の「開発者向け：ローカルイベントを確認」を開きます。直近200件までで、イベント名・ランダムな匿名ローカルID・時刻（Unixミリ秒）・該当する段階番号だけを記録します。入力本文・メール・IPアドレスは記録しません。

| イベント | 発火条件 |
| --- | --- |
| `roadmap_started` | 最初にワークを開く（全削除まで1回） |
| `step_completed` | 未完了から完了へ変わる（完了済みの再確認では増えない） |
| `next_action_opened` | 次の一手のボタンを押す |
| `progress_resumed` | 保存済みの開始済みワークを復元後、初めてワークを開く（ページ表示中に1回） |

再読み込み・復元だけではイベントを追加しません。再開ボタン操作があった場合に記録します。

## 自動テスト

Python 3とNode.js 18以上が必要です。PythonとNode.jsの標準ライブラリだけを使用し、pip/npmインストールは不要です。

```sh
python -m unittest discover -v
```

テストは `preview.html` の実際のインラインJavaScriptを抽出し、Node.jsのVMで実行します。必須／文字数／安全確認、順序・再編集、保存復元・破損・容量不足・削除失敗、匿名イベントの上限と重複防止を確認します。軽量DOM代替によって画面操作の接続、要約、エラー時のフォーカス移動、削除取消も確認します。

実ブラウザーによるレイアウト、ネイティブダイアログのフォーカス制御、スクリーンリーダーの読み上げは、この自動テストの対象外です。

## ブラウザーでの確認手順

1. 全削除後、4段階・進捗0/4・最初の一手を確認します。後続段階がまだ開けないことを確認します。
2. 段階1で空欄・空白だけ・501文字・安全確認なしを試し、理由が表示され完了しないことを確認します。500文字は安全確認後に完了できます。
3. 順に全段階を完了し、1/4〜4/4、7項目のまとめ、入力した検証行動を確認します。まとめから編集し、内容が更新されることも確認します。
4. 保存成功表示の後に再読み込みし、入力・進捗・次の一手が復元されること、再読み込みだけではイベントが増えないことを確認します。ワークを開くと再開イベントが1件追加されます。
5. 削除の取消とEscapeで保持、確定で入力・進捗・イベントがすべて消えることを確認します。
6. 開発者ツールで表示幅を390pxと1280pxにし、主要操作や長い入力が横にはみ出さないことを確認します。コンソールで `document.documentElement.scrollWidth <= window.innerWidth` が `true` となることも確認できます。
7. Tab／Shift+Tabで操作を移動し、フォーカス枠を確認します。Enter／Spaceでボタン・チェックを操作し、削除ダイアログ内のフォーカス移動と取消後の復帰を確認します。

破損時の復旧は、テスト用の入力を保存してから開発者ツールのコンソールで次を実行し、再読み込みします（そのテスト用データは上書きされます）。

```js
localStorage.setItem('ai-business-starter.v1', '{broken');
location.reload();
```

保存失敗は、コンソールで次を実行してから入力します。エラー表示後も編集を続けられることを確認します。

```js
window.originalSetItem = Storage.prototype.setItem;
Storage.prototype.setItem = function () { throw new DOMException('test', 'QuotaExceededError'); };
```

元に戻して「現在の内容で保存し直す」を押し、保存成功を確認します。

```js
Storage.prototype.setItem = window.originalSetItem;
delete window.originalSetItem;
```
